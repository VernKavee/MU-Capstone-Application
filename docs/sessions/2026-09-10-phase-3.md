## Decisions made

- Phase 3 runs one set. The rest timer, the next set, the repair set, and saving are Phase 4
  with the rest of the completion flow (ADR-0004, ADR-0007). The live URL already carries
  reps, sets, and rest, and the header shows "set 1 of N".
- Python enum names are lower case strings in TypeScript (`rep_started`, `countdown`,
  `guiding`). `state` is one of the row's `state_machine.states`, so the UI shows the row's
  names and never re-derives them.
- What the stub does for real: the placement guide judges the landmark bounding box (out of
  frame, head or feet cut, too far, off centre) and the ready gate needs the whole body
  visible with the arms out at shoulder height, both held for eight frames as in the
  research repo. The low confidence guard uses the row's arming joints. What it fakes: once
  active, attempts run on a clock, about one every two and a half seconds, with outcomes
  drawn at random (12% abandoned, 20% incorrect) from the row's rules; frame scope rules show
  mid concentric, rep scope rules on the completion or abandon frame; `rep_stats` are
  invented numbers keyed by rule name. Leftover time carries across states so a slow frame
  rate does not stretch the script.
- The stub's ready pose is the T pose only. The A pose and the T pose that ends a set come
  with the port.
- The skeleton highlight reads `warning_display_rules`, the held list, so the joints stay lit
  as long as the text shows. The research repo lights them from the raw per frame list;
  a rep scope rule fires on one frame, which is invisible at 30 fps.
- Recording: MediaRecorder with the first supported of webm vp9, webm vp8, webm, mp4, held as
  a Blob. Keypoint capture: one object per processed frame with `t` in milliseconds since
  the recording started, the engine state, the event, and the keypoints, so Phase 4 can
  derive attempt frame ranges and state durations (ADR-0003). Both start on the first active
  frame and stop with the set (ADR-0005). The on disk format is still Phase 4's decision.
- MediaPipe: the wasm comes from jsdelivr pinned to the installed version and the model
  from Google's storage, both constants in `lib/live/pose.ts`; self-hosting is a change to
  those two constants. GPU delegate with a CPU fallback. Full model by default; lite is a
  manual choice on the preflight screen and a "Lagging? Use the lighter model" button
  below fifteen frames per second, remembered in localStorage.
- The stage is mirrored, video and overlay together, like a gym mirror; the recording is
  not.
- Sound: a beep per correct rep, a short beep per countdown second and a longer one at go,
  the warning and each new placement cue spoken once when they change. The AudioContext and
  speech are unlocked inside the Start camera click, which is why the preflight exists.
- End conditions checked only while active: target reached, End set pressed, or attempts at
  twice the target. The engine's `ended` phase, which the stub never emits, counts as
  user ended.
- The HUD re-renders only when a displayed value changes; the loop compares a key of those
  values before calling React.
- Design: over live video, off-white ink, one accent (tape yellow) for the warning band and
  the lit joints, bone-white skeleton, one display face for the number and the countdown,
  text buttons in translucent pills, no icons, no cards, no green.
- `tsconfig.json` gained `allowImportingTsExtensions` so `lib/engine` can import `./types.ts`
  for Node's test runner; Next accepts the same imports.

## Facts worth remembering

- The desktop browser pane is a hidden document: `requestAnimationFrame` fires only when a
  screenshot forces a composite, and a `<video>` fed to `captureStream()` stalls. The
  harness that worked: a `<script>` element appended to the DOM (the pane's JavaScript
  tool runs in an isolated world, so a plain override never reaches the page), a canvas
  that copies the test video every 100 ms and calls `requestFrame()`, `getUserMedia`
  returning that canvas stream, and `captureStream()` called before `play()` so Chrome
  does not pause "video-only background media".
- The research repo's webcam recordings are MPEG-4 Part 2 from OpenCV, which Chrome cannot
  decode; `avconvert --preset PresetAppleM4V720pHD` on macOS converts them without ffmpeg.
  `ready_squat_1.mp4` holds the T pose at about 12 s.
- Node 22.17 runs TypeScript tests with `--experimental-strip-types`; imports need explicit
  `.ts` extensions and type-only imports are erased, which is why `stub.ts` can import the
  `RuleBasedLogic` type from `lib/exercise.ts` without pulling Next code into Node.
- Fast Refresh of a non-component module such as `stub.ts` re-runs the live screen's effect
  and restarts the camera session.
- `npx next typegen` must run before `npx tsc --noEmit` knows the new route.
- The tasks-vision package does not export its `package.json`, so the wasm URL carries the
  version by hand.
