## Decisions made

- `exercises.id` is the URL slug: `squat`, `push-up`, `lunge`, `bicep-curl`. A text primary
  key; four rows do not need a uuid, and the evaluation reads the database directly.
- The JSONB shape, enforced by `exercise_logic_valid()`:
  `source`, `state_machine.states`, `state_machine.thresholds` (keys mirror the Python FSM
  attribute names: `thr_standing`, `thr_inflection`, `thr_descending`,
  `hysteresis_buffer`, `consecutive_frames_req`, `start_frames_req`, and for the curl
  `start_descent_delta`, `min_side_score`), `state_machine.arming` (joints and ready tilt
  band, null for the curl, whose FSM has no arming gate), and `rules[]` each with `name`,
  `check`, `priority`, `scope`, `debounce_frames`, `threshold` (keys named per check, so a
  plank can reuse `body_alignment` with `align_min`), `messages` keyed by locale, and
  `highlight_joints`.
- Rule name and check name are separate fields. The four seeded exercises use the same
  string for both; the plank proof used `hip_sag` over `body_alignment`.
- The user's reminder said "one row per rule"; read as one JSON object per rule inside
  `rule_based_logic`, since the report and the build plan both name that JSONB column.
- Messages are verbatim from the Python, title case included ("Lower Your Chest"). They
  are engine data; the export script of ADR-0002 will carry them the same way.
- `name` and `guide_text` are plain text columns as the report specifies. Only rule
  messages are keyed by locale. Flagged below in case the Phase 0 "every user-facing
  message in exercise data is keyed by locale" line was meant to cover them too.
- Guide text is a first draft by this session, three or four sentences each, ending with
  camera placement drawn from the research repo's findings (valgus is a front or 45
  degree rule, lunge trunk tilt is unusable front-on, push-up from the side). Not reviewed
  by the physiotherapy experts.
- `thumbnail_url` and `guide_video_url` are null; the UI shows a labelled placeholder.
- Setup defaults: 10 reps, 3 sets, 60 s rest. Limits 1 to 100, 1 to 10, 0 to 600. The
  numbers travel to the guide in the query string through `next/form`; nothing is stored
  until the first set is saved (ADR-0004).
- `expert_motions`: no app role has any privilege. Punnapat's component writes it over a
  direct connection (ADR-0007).
- Frame-rule debounce is per rule (10 for frame rules, 1 for rep rules) rather than a
  global constant, so a future rule can differ.

## Facts worth remembering

- A NULL result passes a CHECK constraint, and `jsonb_typeof` of a missing key is NULL,
  so every comparison in `exercise_logic_valid()` is wrapped with `is true`. The first
  version let a rule without an English message through; the pgTAP test caught it.
- The advisors flag any function without a fixed `search_path`.
- In the hidden browser pane, a script that submits a `next/form` before React hydrates
  falls back to a native GET; clicking the button after hydration navigates client-side.
- Research repo at c5fc57c: the squat back-tilt bar is 55 (was 45), the knee-past-toe rule
  was replaced by `knee_valgus`, the lunge back-knee bar is 135 (was 100). The header of
  `form_rules.py` still says every threshold is pending a physiotherapy review, so the seed
  will need re-typing or the export script before the evaluation.
- The research repo's registry also maps `diamond_pushup`, `dumbbell_hammer_curls`,
  `drag_curl`, and `dumbbell_reverse_lunge` to the same rulesets; those are aliases for
  benchmarks, not app exercises.
