## Learned

- This machine runs containers on Podman, never Docker Desktop. The Supabase CLI needs
  `DOCKER_HOST=npipe:////./pipe/podman-machine-default`, since the docker CLI's context points
  at Docker Desktop. The pipe was missing at first: a stale
  `%LOCALAPPDATA%\Temp\podman\podman-machine-default-api.sock` from the day before stopped
  `win-sshproxy`; deleting it and restarting the machine brought the pipe back. The database and
  the knowledge base survived in the Podman volumes; the clock inside matched the host.
- The squat's "good" set was not clean to the engine: 5 of 16 correct, `knee_varus` and
  `rounded_back`. The curl's intended fault came out as `elbow_flare` rather than `partial_curl`.
  So the pilot has clean control sets for the curl only.
