## Decisions made

- Keypoint file: JSON gzipped in the browser, 231 numbers per frame with `t`, `state`, and
  `event`, plain JSON where `CompressionStream` is missing. Recorded in ADR-0005.
- Feedback history bound: the five most recent other workouts of the exercise, finished or
  not, as set summaries without attempt records. Recorded in ADR-0007.
- `keypoints_url` and `video_url` hold storage object paths, not URLs, so nothing stored
  expires. History signs a download URL when it plays the video.
- Attempt records: `schema_version` per record, `threshold` is the rule's threshold
  object, and `value` is `rep_stats[rule name]`. Recorded in ADR-0003.
- Order after a set: save the row, upload both files, then analyse. Analysis waits for
  the video upload as well, marked in `pipeline.ts` with a `ponytail:` comment.
- Every step of a set's job remembers what it finished, so Retry redoes only what is
  missing. The analyse step writes only the file paths that arrived.
- Each set's save waits for the previous save to settle, so all sets share one workout
  row even with a rest of zero.
- The repair set is offered after an initial set with any violation, abandoned attempts
  included. It starts at once with the same set number. A skip writes `repair_declined`
  on the initial set; a skip pressed before the save lands is remembered and written
  after it.
- The rest timer runs on the set-complete screen and starts the next set at zero, with a
  beep; Start now skips it. A rest of zero starts the next set at once, so its feedback
  is first read on the finished summary. Recorded in ADR-0004.
- Finish workout waits for the last save, writes `ended_at`, and opens the summary. It
  does not wait for feedback.
- The finished summary reads from the database, so it survives a reload and proves the
  save. It has no retry; the retry lives on the set-complete screen, as ADR-0007 asks.
- The completion flow's server actions return errors as values, since the live screen
  calls them directly rather than through a form.
- Column grants: the API may update `workouts.ended_at` and, on `sets`, the decline, the
  file paths, similarity, feedback, and attempts. The engine report and totals are never
  rewritten.
- The server logic takes the Supabase client as a parameter and imports with `.ts`
  extensions, so a Node script can run it against the stack. The actions stay thin.
- The set-ended handler and the rest timer use React 19.2's `useEffectEvent`, so the
  camera effect does not restart when the workout state changes.

## Facts worth remembering

- A "use server" file may export only async functions; the bucket name moved to
  `lib/set.ts`.
- `createSignedUploadUrl` with `upsert` needs both the insert and the update storage
  policy for the user.
- `npm run db:reset` deletes every local auth user, so each new migration signs everyone
  out of the local app.
- A Node script under the scratchpad resolves the repo's packages with
  `createRequire(repo + "/package.json")` and runs as `.mts` for top-level await.
