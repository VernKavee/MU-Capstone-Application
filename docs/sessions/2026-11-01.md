## Writing a missing feedback later (Sujira)

### Done

- A set without feedback gets "Write feedback now" on the finished summary and on History
  level 4. Before, the only retry was on the set-complete screen, so a set whose feedback
  failed (service down, timeout) and was left behind had no feedback for good.
  `retryFeedback` in `app/(app)/history/[exercise]/[workout]/actions.ts` calls
  `analyseSet` with no new files, which redoes only what is missing: similarity when the
  set has a keypoint file and no score, then feedback. A failure comes back as `?error=`
  beside that set and goes to the server log; a similarity error beside written feedback
  is not shown. Pressing it on the finished summary while the first feedback is still
  being written calls the model twice; nothing breaks.
- `e2e/retry-feedback.spec.ts`: a seeded finished workout with one unanalysed set. It
  passed with `FEEDBACK_URL` pointing at nothing (error shown, button stays on both pages)
  and with it pointing at a local fake service answering like RAG_SYSTEM's (feedback
  written, button gone on both pages). No model was called.
- The analyse error is also logged on the server (`9029a67`).

### Learned

- On this Windows machine the container VM has 2.8 GB. Right after `npx supabase start`
  (restored from backup), password sign-in through the app timed out in Auth
  ("Processing this request timed out") while the dev server compiled; the isolation spec
  failed the same way. It went away once the stack had run a while. The dev server's
  first start also takes longer than Playwright's 60 s, so start it first.
- `app/(app)/time-zone.tsx` refreshes the page on the first visit without the `tz`
  cookie, which can abort a test's own `page.goto`. The new spec sets the cookie and the
  browser's zone up front.
- Stopping `npm run dev` as a background task leaves Next's `start-server.js` running on
  Windows; it has to be stopped by its process id.
